# 设计：星灵「逆碎裂·重组」开场 / 转场动画

> 状态：已批准（2026-11-28）。下一步：实施计划。


## 意图与原因
用户学了两篇 Blender 碎石场景教程（上篇：Voronoi 碎裂地面 + 几何节点体积散布 + 推镜；下篇：能量方块、体积雾、发光颗粒、圆环湍流），想做一个**同一水准的原创项目**，并且**放进星灵 App**。
它的作用是开场和转场：打开 App 时、切换角色时，播放一段「碎片重组成角色」的动画，最后平稳落到 App 现有的角色展示画面，用户接着正常查看角色。

## 创意：B「逆碎裂·重组」（用户已选）
**开场，约 4–6 秒，可点一下跳过：**
1. **虚空（0–1 秒）**：深色星云背景上，几百块碎片按噪波漂移、自转。这对应教程 `scatter` 的随机旋转/缩放 + 噪波漂移。
2. **汇聚（1–3 秒）**：碎片沿曲线飞回原位，拼出一段短的碎石道路和圆形站台。镜头同时线性推进。碎片归位时，缝隙闪一下青色光。
3. **角色显形（3–4.5 秒）**：**角色本身也由碎片拼成**（用户已选）。碎片从外向内或从脚到头依次归位，背后有光环和辉光。
4. **落点（4.5–5 秒）**：拼合完成时辉光冲到峰值，在峰值下碎片角色换成当前显示的角色模型，然后辉光收敛；道路和站台化成粒子淡出；镜头停在展示机位。

**转场（切换角色）**：先倒放，当前角色和站台碎裂飞散，碎片进入虚空漂移；再对新角色正放汇聚。

## 目标
- 实时在手机上运行，使用 App 现有的 Filament 1.56 引擎，与角色无缝衔接。
- 碎片拼合后与原模型外观一致（保留原 UV、8 个材质和贴图），换模型发生在辉光峰值下，肉眼看不出切换。
- 开场和转场共用一套机制，只是播放方向不同。
- 技法与教程对应，包括 Voronoi 碎裂、散布、噪波漂移、推镜、辉光、雾、发光颗粒，便于用户对照学习。

## 非目标
- 不实时切割模型（31 万面在手机上切不动）。
- 不做 Blender 级的真实体积光，雾和光束用 Filament 的雾和辉光近似。
- 不做预渲染视频。
- 不改动角色的原始 PBR 材质和原始资产字节。

## 反目标（技术上能跑，但这样就算失败）
- 拖慢 App 启动：资产没准备好时，不能等，要直接进入正常画面。
- 中低端机掉帧严重、发烫。
- 落点那一刻能看出模型切换：跳帧、光照变化或位置偏移。
- 动画遮住角色太久，或者不能跳过。
- 私有角色资产或碎片资产进入 GitHub。

## 约束（来自现有项目）
- 原生端：`native-v3/bootstrap.sh` 生成 Android 工程（包名 `com.xs.character.viewer`，Kotlin，Filament 1.56 + gltfio + ModelViewer）。界面是叠在上面的 WebView（`viewer.html`）。
- 逐帧回调已有：`Choreographer` 的 `ticker`（`bootstrap.sh` 约第 90–99 行）。根节点变换走 `viewer.engine.transformManager`（约第 926 行）。
- Filament 1.56 只有一盏方向光（代码注释），补光用点光和聚光。App 当前未启用 Bloom 和 Fog。
- 资产：`mobile.glb` 约 31 万面、2K 贴图；`native_full.glb` 约 196 万面、8 个语义材质（semantic8）。角色资产私有，不进仓库。
- 签名资产包（V8.0，`scripts/build-signed-asset.py` 与 `bootstrap.sh` 约第 2221 行）目前只接受 `profile == "semantic8"`，并绑定固定的 `sourceSha256`。碎片资产需要新增一个类型。
- 签名必须使用原永久证书（SHA-256 `065d80dd…`），私钥和密码不得进仓库或日志（见 `docs/SESSION-HANDOFF.md`）。
- 只有 CI 编译通过不算完成，必须真机验收（项目惯例）。

## 做法
考虑过的三种：
1. **离线预切 + 实时播放（已选）**：用 Blender 脚本，复用已验证的 `blender/shattered-realm/shattered_realm.py` 里的 Voronoi 思路，扩展成三维切割。把角色模型预先切成几百块，导出「碎片版 GLB」。App 用 Filament 逐块移动碎片，播完换回原模型。光照材质与 App 一致，开场和转场都能用。代价是每个角色多一份资产，还有几百次绘制调用。
2. 着色器假碎裂：不加资产，但必须替换原生 glTF 材质（违背「原始 PBR 不改动」），边缘会撕裂。未选。
3. 预渲染视频：画质最高，但每个角色、每个方向都要渲染，最后一帧光照对不上实时画面，安装包也会变大。未选。

## 已定的部分
- **碎片资产生产（离线，本地）**：新脚本 `blender/shatter-intro/fracture_character.py`。
  - 输入角色 GLB（优先 `mobile.glb`），输出碎片版 GLB。每块碎片是独立节点，节点原点在碎片质心，节点的初始变换就是「归位」状态，保留原 UV、材质名和贴图（单一 buffer、内嵌贴图）。
  - 切割用三维 Voronoi 种子点，在 Blender 里做布尔切割或按面归属分组。块数可配置，目标 200–400 块。
  - 另附每块碎片的元数据：质心、包围半径、归位顺序值（例如按高度），存成 JSON 或 glTF extras。
  - 环境碎片（道路和站台）同样由这个脚本生成，用的是 `shattered_realm.py` 的二维 Voronoi 石板算法。
- **App 播放**：新增原生模块（Kotlin，例如 `ShatterIntro`）。
  - 从 `ticker` 每帧驱动；用 `TransformManager` 设置每块碎片的变换。
  - 动画函数在原位与「虚空位置」之间按时间曲线插值；虚空位置由噪波和随机旋转决定，用固定种子保证可复现。
  - 播完后隐藏碎片资产、显示原模型；转场时反向播放。
- **视觉**：动画期间临时开启 Filament `BloomOptions` 与 `FogOptions`；背景用程序化星云（天空盒或全屏着色）；角色背后的光环用发光颗粒（实例化小几何体）。结束时恢复 App 原设置。
- **资产分发**：扩展签名资产包协议，新增碎片资产类型。仍用原永久证书签名、哈希校验，并且只能从本地导入，与 V8.0 一致。
- **安全退路**：碎片资产缺失、校验失败，或检测到性能不足时，跳过动画直接进入现有画面。用户可以在设置里关闭开场动画。

## 多角色（用户已定：以后要支持多个角色）
- 本项目范围：**开场动画 + 按角色绑定的碎片资产协议**。协议从一开始就按「一个角色对应一份碎片资产」设计：payload 带 `characterId` 和 `sourceSha256`（碎片是从哪份显示模型切出来的），新类型 `profile: "shards1"`。导入后只作为该角色的开场资产登记，**永远不会被当成可显示模型**（不进 `selected="imported"`）。
- 转场（角色 A 碎裂 → 角色 B 重组）的播放模块本项目就做好，支持正放和倒放，并用当前唯一的角色自测。但「角色列表 / 切换角色」本身是**另一个独立项目**，等它落地后再把转场接上。

## 我替你定的（请过目，可改）
1. **碎片从 `mobile.glb` 切**：轻量，切割和内存都可控。落点不追求逐像素一致，改用**辉光峰值遮挡切换**：拼合瞬间辉光冲到顶点约 150 ms，在峰值下把碎片换成当前实际显示的模型（任何画质模式、任何运行时材质都适用），然后辉光收敛。这样不用为每种画质模式、每套运行时材质各做一份碎片。
2. **动画和加载并行**：开场期间同时加载原模型，虚空阶段可以循环漂移，最多延长 3 秒等待加载。还没好就照常拼合碎片角色并停在落点，模型就绪后再在辉光下替换。动画本身不额外增加等待。只有碎片资产缺失时才直接跳过动画。
3. **落点后道路和站台化成粒子淡出**，展示画面保持现在的样子（无地面），不影响现有的阴影、光照和截图对照。
4. **动画期间隐藏 WebView 界面、锁住手势**，点一下跳过。镜头落到用户上次保存的姿态（没有则用默认机位）。
5. **内存保护**：碎片资产与原模型同时驻留，如果设备内存低于阈值（实施时实测确定），就只在模型已缓存的热启动时播放。

## 留给实施者决定
- 三维切割的具体实现（布尔、按面归属，或 Cell Fracture 扩展可用时用它），以落点无缝为准。
- 碎片块数、动画时长和缓动曲线的具体数值，在真机调试后确定。
- 碎片元数据存放在 glTF extras 还是旁挂 JSON。
- 星云背景是天空盒贴图还是程序化着色器。

## 验证
- 本地：Blender 脚本对一个可公开的测试模型（例如 Suzanne 或自制人形）跑通，导出的碎片 GLB 在「全部归位」状态下与原模型逐像素对比（Blender 或 Filament 离屏渲染），差异接近 0。
- CI：`native-v3` 工作流编译通过。
- 真机：开场、跳过、转场正放和倒放、资产缺失时的退路都要测；记录帧率与温度；落点前后各截一帧做 A/B 对比。
- 私有资产和签名材料不出现在提交、日志和 Actions 输出里。
